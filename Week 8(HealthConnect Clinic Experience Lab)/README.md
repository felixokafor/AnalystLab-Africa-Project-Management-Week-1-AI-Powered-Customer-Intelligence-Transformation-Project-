> AnalystLab Africa Experience Lab Internship Programme — Project Management Track

## Project Overview

HealthConnect Clinic is a fictional outpatient healthcare provider seeking to reduce missed appointments and improve the patient support experience through data and AI.

The central project question was:

> **How can HealthConnect Clinic use data and AI to reduce missed appointments and improve the patient support experience?**

This project was completed as part of the AnalystLab Africa Experience Lab Internship Programme.

My role was **Project Management**, with responsibility for planning, execution coordination, risk and dependency management, integration coordination, testing coordination, documentation, and final project readiness.

---

## Project Objectives

The project focused on:

- Understanding the appointment attendance problem.

- Coordinating multidisciplinary workstreams.
- Managing project tasks, timelines, risks, and dependencies.
- Supporting cross-track integration.
- Coordinating testing and validation activities.
- Documenting project decisions and issues.
- Assessing final project readiness.

# Cross-Track Collaboration

A verified cross-track collaboration was completed between:

**Data Analytics → Project Management**

### Component tested

**No-Show Rate by Previous No-Show Group**

The Data Analytics track provided underlying appointment counts and calculated no-show rates for three previous-no-show groups.

| Previous No-Show Group | Total Appointments | No-Show Appointments | No-Show Rate |
|---|---:|---:|---:|
| 0 | 2,921 | 1,271 | 43.5% |
| 1–2 | 1,986 | 1,088 | 54.8% |
| 3+ | 93 | 64 | 68.8% |
| **Total** | **5,000** | **2,423** | **48.5%** |

### Testing result

**PASS**

The expected and actual rates were consistent.

No corrective calculation was required.

### PM contribution

The Project Management track:

1. Reviewed the testing evidence.
2. Recorded the underlying counts and calculated rates.
3. Documented the validation result.
4. Recorded the cross-track integration activity.
5. Carried the validated finding into the final readiness assessment.
6. Avoided creating an unsupported corrective issue because the test passed.

The collaboration therefore changed the **project evidence and readiness records**, rather than changing the underlying analytical result.

# Limitations

The project has several documented limitations.

- I could not independently verify final technical testing evidence from every technical workstream.
- Full end-to-end technical integration could therefore not be independently confirmed from the evidence available to me.
- The Data Analytics work contains documented dataset limitations.
- Some relationships in the appointment data were not tested.
- Missing data exists for some fields in the dataset.
- The final project communication must distinguish verified evidence from pending technical evidence.

These limitations were documented rather than replaced with assumptions.

---

# Key Project Management Lessons

### 1. Planning is only the starting point

A project plan must evolve into actionable tasks, controls, and evidence.

### 2. Track evidence, not assumptions

A status should reflect what can actually be demonstrated.

### 3. Dependencies need active management

Cross-track dependencies can affect testing, integration, and final readiness.

### 4. Testing should produce documented evidence

A test result should be traceable from the expected result to the actual result and final status.

### 5. Not every failed expectation requires a correction

In the verified analytics test, the result passed, so no corrective calculation was required.

### 6. Limitations should be visible

A professional project manager should identify what is known, what is verified, and what remains unverified.
